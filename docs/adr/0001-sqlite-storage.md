# Хранение: SQLite-файл и целостность занятости на уровне приложения

Хранение — один SQLite-файл (`apps/backend/data.db`), а не in-memory и не внешний сервис: файл переживает перезапуск и не тянет инфраструктуру, что для учебного проекта — правильный баланс. Правило «на одно время одна бронь» проверяется в приложении в транзакции, а не ограничением БД: SQLite не умеет range-exclusion, а `UNIQUE(start_at)` не покрывает пересечение интервалов разной длительности.

## Consequences

- Схема: `event_types(id, name, description, duration_minutes)` и `bookings(id, event_type_id, start_at, guest_name, guest_email)`; `bookings.event_type_id` ссылается на `event_types.id`; `CHECK (duration_minutes >= 1)`. Таблицы слотов нет — слоты вычисляются на лету.
- `start_at` хранится текстом ISO 8601 со смещением `+03:00` (как в контракте); МСК фиксирован, лексикографическое сравнение корректно.
- Файл в `.gitignore` (`*.db`); тесты используют временный файл на прогон.
